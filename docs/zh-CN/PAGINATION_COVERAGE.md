## 2. 已接入但仍需按页面补充验收

目前没有已知的标准数据库分页页面停留在“仅代码接入、尚未真实验收”状态；EMIAS 的环境阻断已于 2026-09-08 解除。

补充说明：`/portal/data/datasets` 已切换为 `apiGetDatasetPaged` 远程模式，复用数据资源分页接口；本次已在 VPN、服务和权限可用时完成真实 Network 验收。`/portal/data/models` 仍保留 `apiGetDataset` 本地模式，因为模型首页需要先拉取完整集合后按组织聚合。

## 3. 有意保留本地模式或暂不套用

| 页面/组件 | 数据来源 | 判断 | 原因 |
| --- | --- | --- | --- |
| 门户总览节点、集群节点、节点标记、节点详情 | Kubernetes API / 节点快照 | 暂不改 | 这是资源快照和汇总，不具备数据库 `total` 语义；若未来数据规模明显增长，应单独设计快照分页 |
| 作业详情 Pod 表 | Kubernetes API | 暂不改 | 单个作业下的 Pod 明细，属于详情级快照；先保证详情刷新和状态展示 |
| 文件系统表、数据集文件目录 | storage-server | 暂不改 | 目录浏览依赖路径和游标语义，不能直接伪装成数据库 `page/page_size` |
| 表单下拉框、候选项 | 用户、账户、资源、镜像等全量接口 | 暂不改 | 需要完整集合、搜索和已选项回显；后续应做异步选择器，而不是把分页表格组件塞进去 |
| 审批等组件的本地兼容分支 | 已有调用方传入完整数组 | 保留 | 远程主页面已经使用新模式，本地分支用于兼容旧调用方 |

## 4. 剩余页面分类结论

### A. 应继续推进的候选

优先检查“数据库主列表、数据会增长、已有明确页面入口”的页面。账户成员、镜像、镜像构建、模型下载、操作日志、定时任务记录、集群资源、管理账户、用户、数据集主列表和 EMIAS 已经完成代表性真实验收。后续重点是补充更多权限范围和页码边界案例。这些页面适合复用既有分页协议，但每个页面仍要单独确认权限、筛选字段和排序白名单。

### B. 需要先做专项设计的页面

节点/Pod 资源列表和文件目录不应直接复制 JobTemplate 的实现。前者要考虑 Kubernetes list/watch、快照一致性和资源聚合，后者要考虑目录路径、游标、文件变更和大目录读取。它们可以将来分页，但协议未必是数据库页码协议。

### C. 暂时不应做的事情

- 不为了“页面数量多”而逐个机械改接口。
- 不删除旧 `/jobtemplate/list`、旧 `/aijobs` 等仍有调用方的接口。
- 不修改 CLI；CLI 迁移应在调用方清点和兼容窗口后单独安排。
- 不把只有编译通过或接口可访问的结果写成真实数据验收通过。

## 5. 当前推荐顺序

1. 以 JobTemplate 作为标准样例，冻结公共协议和 DataList 远程模式边界。
2. 保持共享文件和数据集共享成员的远程实现，补充有数据环境下的跨页和权限验收。
3. 账户成员和数据集主列表的跨页、搜索、页大小和空结果已完成真实验收；后续补充更多账户和权限范围测试。
4. 对镜像详情预取的历史记录提示做独立排查，避免与分页问题混在一起。
5. 最后讨论 Kubernetes 快照和文件目录的专用方案。
